# 011: Image Tools Systematic Review

Date: 2026-10-01
Area: Editor / raster image preview and editing
Trigger: Reports that image editing is unusable, crop does not apply reliably, and crop can rotate the image
Scope: Read-only static review; no application launch, build, or test execution

## 1. Executive summary

- **The raster editor is unsafe for production-quality edits.** When the primary thumbnail decode succeeds, crop and save use a viewport-sized working representation clamped to 1024–4096 pixels rather than the original source; any source larger than that dynamically selected proxy can therefore be silently reduced (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:225-273`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:109-115,131-176`).
- **“Crop does not work” has two confirmed causes.** Apply Crop maps top-origin canvas Y through an additional inversion, while Save accepts an uncommitted crop marquee but does not composite it; successful save then clears that marquee (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:17,28-34,117-128,139-166`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasViewRendering.swift:4-8,84-135`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImagePreviewHost.swift:83-92`).
- **The code confirms inconsistent orientation handling, but not that Crop itself causes a quarter-turn.** The primary thumbnail path applies the source transform, the fallback decode does not request it, crop discards source properties, and export does not explicitly preserve orientation or write orientation 1; this is a candidate explanation for reported rotation that requires EXIF 1–8 runtime fixtures (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:225-258`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:145-176`; `projects/crispyvibes/crispyvibes/Data/Services/RasterImagePersistenceService.swift:40-71,105-112`).
- **Recovery is broken.** Applied crop replaces the working bitmap, but Clear removes only transient overlays and ignores the bitmap-mutation flag, so it can report “Nothing to clear” while the image remains cropped and dirty (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:28-34,81-90,170-188,273-279`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:425-434`).
- **The basic macOS workflow is incomplete.** Draw is the default, Pan has no toolbar button or drag implementation, Copy has no UI action, and the app-level Save shortcut reaches a text-save method that rejects image documents (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImagePreviewHost.swift:4-9,41-49,74-99`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:92-98,200-249`; `projects/crispyvibes/crispyvibes/App/AppDelegate.swift:245-263`; `projects/crispyvibes/crispyvibes/Features/Editor/Views/MarkdownEditorView.swift:150-152`; `projects/crispyvibes/crispyvibes/Features/Editor/ViewModels/MarkdownViewModelEditing.swift:108-110,196-198`).
- **Architecture is inverted.** SwiftUI state, coordinator tokens, mutable canvas state, decode, observation, and persistence are mixed in UI types; the canvas directly calls a static persistence utility instead of an injected view-model/service boundary (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImagePreviewHost.swift:36-50,137-158`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:35-51,176-258,395-470`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:28-49,109-115`; `.kiro/steering/coding-guidelines.md:14-34`).
- **The specs overstate implementation status.** The feature spec requires Copy, keyboard Cancel, reset-to-original, backing-scale fidelity, and progressive loading, while the implementation omits or only partially implements them; threat-model claims for progressive/bounded work, keyboard accessibility, and file-operation logging are unsupported, and open-time URL standardization (`projects/crispyvibes/crispyvibes/Features/ContentViewer/Models/ContentViewerTab.swift:10-17`) does not resolve symlinks or check device/inode identity, so it does not mitigate the T05 TOCTOU risk it is credited with (`specs/features/editor/previews/spec.md:16-17,40-50,104-109,183-210`; `specs/features/editor/previews/threat-model.md:56-61,73-90`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:156-169,225-258,425-490`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:200-270`).

## 2. Critical bugs

### P0 — Save discards an uncommitted crop

**Root cause.** A non-nil `cropSelection` counts as pending work and enables Save (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:28-34,200-210`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImagePreviewHost.swift:88-92`). Export draws the working image, strokes, and annotations but not the crop operation, and successful save clears the selection (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasViewRendering.swift:4-8,84-135`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:117-128,273-279`). Switching to Draw or Annotate does not clear the selection, but the marquee is rendered only in Crop mode; the user can therefore hide the still-dirty crop and save an uncropped recompression (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImagePreviewHost.swift:163-171`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasViewRendering.swift:66-72`).

**Fix.** Make the marquee transient selection state, not a committed edit. Disable Save while a crop awaits Apply; enable Apply only for a valid pixel rectangle; preserve a visible pending indicator across tool switches or require explicit Apply/Cancel before switching. Return should apply and Escape/Cancel should discard.

**Regression tests.** Add canvas/state tests under `projects/crispyvibes/tests/unit/Features/Editor/`: selection does not become persistable output; Save is blocked with a marquee; switching Crop → Draw/Annotate cannot hide-and-save it; Apply commits exact dimensions; Cancel preserves pixels. Put button, Return/Escape, and VoiceOver behavior in the UI-test target. Keep the existing composition file limited to host-mount smoke coverage, consistent with the repository’s mirrored test-layout rule (`AGENTS.md:52-59`; `projects/crispyvibes/tests/unit/App/Views/ViewCompositionSmokeTestsPreviews.swift:49-100`).

### P0 — Applied crop selects the wrong vertical region

**Root cause.** The canvas is flipped and mouse input is already converted into bounded, top-origin canvas coordinates (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:17,200-269`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasViewGeometry.swift:4-10`). Crop first rounds the point-space selection with `.integral`, then scales it, then reverses Y with `imageRect.height - normalizedSelection.maxY` before `CGImage.cropping(to:)` (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:139-166`). This conflicts with the editor’s current top-origin pixel-row contract and maps a top selection toward the opposite vertical band.

**Fix.** For this contract, map all four edges before rounding: `pixelMinX = floor(pointMinX × scaleX)`, `pixelMinY = floor(pointMinY × scaleY)`, `pixelMaxX = ceil(pointMaxX × scaleX)`, and `pixelMaxY = ceil(pointMaxY × scaleY)`. Use top-origin `pointMinY`; do not use `imageHeight - pointMaxY`. Clamp the edge values once to `[0, pixelWidth] × [0, pixelHeight]`, then derive width/height and validate the final pixel rectangle. Remove point-space `.integral` and the pre-pixel 2×2 check (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:139-164`).

**Regression tests.** Under `tests/unit/Features/Editor/`, crop each corner of a non-square four-quadrant fixture and assert exact colors, bounds, and dimensions. Cover reverse drags, fractional edges, non-uniform point-to-pixel scale, 1×/2× backing scale, and zoom 0.1×/1×/10×. Current geometry tests only validate centering insets (`projects/crispyvibes/tests/unit/App/AppShell/AppShellModelTestsFormattingAndUpdates.swift:202-226`).

### P0 investigation — Reported crop-triggered rotation

**Confirmed facts, not yet a proven causal root cause.** The primary thumbnail decode requests `kCGImageSourceCreateThumbnailWithTransform: true`; only the fallback calls `CGImageSourceCreateImageAtIndex(..., nil)`, and a final fallback uses `NSImage(contentsOf:)` (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:225-258`). Crop acts on whichever representation was loaded and creates a metadata-free `NSImage` from cropped pixels (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:145-176`). Persistence emits one new frame with compression properties only and does not explicitly write source orientation or orientation 1 (`projects/crispyvibes/crispyvibes/Data/Services/RasterImagePersistenceService.swift:40-71,105-112`). Thus the fallback can already be incorrectly oriented at load, whereas the primary path is transformed before crop; static code does **not** prove that invoking Crop causes a 90°/270° turn. A separate manual Y flip in off-screen composition could cause vertical mirroring, but its exact rendered direction also requires a pixel fixture (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasViewRendering.swift:118-130`).

**Fix.** Normalize all decode paths exactly once into canonical upright pixels, retain orientation metadata separately, and export normalized pixels with orientation 1. Use one explicit render coordinate system for base pixels and overlays; do not combine implicit AppKit flippedness with an independently mutated CGContext transform.

**Regression tests.** Under `tests/unit/Features/Editor/`, use asymmetric JPEG and HEIC fixtures for EXIF orientations 1–8 and force each decode branch. Assert preview orientation before crop, then crop/save/reopen and assert pixel positions, dimensions, and output orientation 1. Add top-only text/stroke fixtures comparing live, copied, saved, and reopened output. Until these reproduce the report, label the issue “confirmed orientation inconsistency; crop-trigger attribution open.” Existing direct raster tests have no crop or orientation-sensitive assertions (`projects/crispyvibes/tests/unit/App/Views/ViewCompositionSmokeTestsPreviews.swift:49-100`).

### P0 — Editing can overwrite an original with preview-resolution pixels

**Root cause.** The primary decode path requests a thumbnail whose dynamic target is clamped to 1024–4096 pixels; when that decode succeeds, the proxy is installed as `workingImage` and crop/save operate on it. If thumbnail creation fails, the code instead attempts an uncapped full-resolution decode and then `NSImage(contentsOf:)` (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:225-273`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:66-78,109-115,131-176`).

**Immediate fix.** Phase 0 should block overwrite when source pixel dimensions exceed the working representation, with an actionable “editing this preview would reduce resolution” message. Do not synchronously substitute full-resolution export in the current UI update path: decode/command dispatch/encode run from `updateNSView`, and composition immediately allocates a four-channel bitmap (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:391-470`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasViewRendering.swift:84-135`). Full-resolution cancellable export belongs in Phase 1.

**Regression tests.** Phase 0 must cover: (a) a >4096-pixel source, (b) a source below 4096 but larger than the computed proxy—for example, 3000 pixels with a 1024-pixel request—and require both to refuse destructive proxy overwrite; (c) a source no larger than its working representation and require Save to remain available; and (d) forced full-resolution fallback and require the safety gate not to block when working and source dimensions match. Phase 1 tests must prove full-resolution crop dimensions, cancellation, bounded peak memory, and responsive UI (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:244-273`).

### P1 — Clear cannot revert an applied crop

**Root cause.** Applied crop replaces `workingImage` and sets `hasUnsavedBitmapMutations`, while Clear ignores that flag and removes only transient state (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:28-34,81-90,170-188,273-279`). This contradicts the specified reset-to-original behavior (`specs/features/editor/previews/spec.md:43-44,193-196`; `specs/features/editor/previews/technical-design.md:61-65`).

**Fix.** Retain an immutable baseline; separate Cancel Selection, Undo, and Revert All; derive action availability from document and saved revisions.

**Regression tests.** Crop → Revert restores exact original pixels/dimensions; crop → Undo → Redo round-trips; failed save preserves history; successful save marks only the submitted revision clean.

## 3. UX problems, prioritized

### P0 — Unsafe and misleading

1. **Draw is the initial mode**, so ordinary dragging starts a stroke; Pan is absent from the toolbar (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImagePreviewHost.swift:4-9,41,74-80`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:211-214,231-249`). Default to Preview/Select/Pan.
2. **Action states do not reflect validity or activity.** Apply is enabled for any Crop mode, Clear is always enabled, and there is no `isSaving` state to prevent repeated save or edits during completion (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImagePreviewHost.swift:41-49,83-99`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:444-470`).
3. **There is no Undo/Redo**, and Clear cannot restore applied crop (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:36-49,81-90,170-188,211-279`).
4. **⌘S does not save images.** The shortcut posts `.saveCurrentMarkdown`, which calls `viewModel.save()`; that method rejects document types outside a list that excludes `.image` (`projects/crispyvibes/crispyvibes/App/AppDelegate.swift:245-263`; `projects/crispyvibes/crispyvibes/Features/Editor/Views/MarkdownEditorView.swift:150-152`; `projects/crispyvibes/crispyvibes/Features/Editor/ViewModels/MarkdownViewModelEditing.swift:108-110,196-198`).

### P1 — Crop, navigation, and clipboard are unusable

1. **Crop is a one-shot rectangle** with no handles, move/resize, dimensions, ratios, outside dimming, grid, or keyboard adjustment (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:200-210,231-243`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasViewRendering.swift:66-82`).
2. **Pointer drag-pan is not implemented.** `.pan` forwards mouse-down to `super`, while mouse-drag does nothing; pinch magnification and scrollbars exist, but Pan is not selectable in the toolbar (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:200-205,231-249`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:337-348`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImagePreviewHost.swift:74-80`).
3. **Copy is unreachable.** The canvas method exists, but the action row omits it, contrary to F009-R03/S04 (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:92-98`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImagePreviewHost.swift:74-99`; `specs/features/editor/previews/spec.md:16-17,104-109`).
4. **External reload erases dirty work without offering a choice.** Reload records pending state, replaces the image (which clears edits), then reports the loss (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:176-210`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:66-78`).

### P2 — Markup, accessibility, and feedback are prototype-level

1. Drawing is fixed at a 2.2-point green stroke with no style, eraser, selection, or delete controls (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:281-324`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasViewRendering.swift:10-21`).
2. Text annotations are appended as fixed orange/white bubbles and have no object-selection/editing state (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:36-49,215-227`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasViewRendering.swift:24-63`).

4. The canvas is mouse-only, there is no Cancel action, and status updates have identifiers but no accessibility announcement in the reviewed path (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:200-270`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImagePreviewHost.swift:74-157`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:331-359`). This misses F009-S13/S14 (`specs/features/editor/previews/spec.md:178-191`).
5. Toolbar labels, hints, statuses, and failures are hard-coded despite existing localized image action keys, contrary to repository convention (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImagePreviewHost.swift:47-49,61-125`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:420-468,493-519`; `projects/crispyvibes/crispyvibes/Shared/Support/AppStrings.swift:2612-2637`; `.kiro/steering/coding-guidelines.md:89-94`).

## 4. Architecture issues, prioritized

### P0 — No non-destructive document model

The canvas owns the only bitmap, selection, overlays, dirty state, input, crop mutation, compositing, pasteboard, and save finalization; crop replaces the bitmap and no baseline/history exists (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:28-49,66-188,200-331`). Introduce an immutable source-backed `RasterImageDocument` and reversible `ImageEditOperation`s; keep the canvas as an input/render adapter.

### P0 — Preview and export are the same pipeline

When the primary thumbnail branch succeeds, viewport, backing scale, and zoom select a capped proxy that also becomes the destructive edit/export source (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:225-273`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:109-176`). Separate immutable full-resolution source data, discardable display proxies, and cancellable off-main export.

### P1 — Layer ownership violates project conventions

The host owns token commands, the representable coordinator owns observation/decode/workflow/status/save, and the canvas calls static concrete persistence (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImagePreviewHost.swift:36-50,83-158`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:35-51,60-324,395-470`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:109-115`; `projects/crispyvibes/crispyvibes/Data/Services/RasterImagePersistenceService.swift:29-40`). This conflicts with `Views → ViewModels → Services → Protocols` and `AppContainer` injection (`.kiro/steering/coding-guidelines.md:14-34`).

### P1 — Orientation, coordinates, save revision, and file identity are implicit

Flipped input, crop Y reversal, branch-specific orientation handling, and export CTM mutation are spread across three types (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:17,131-166`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:238-258`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasViewRendering.swift:118-130`). Save completion clears current transient state without checking the submitted revision, while file change detection compares only size and modification date (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:444-490`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:117-128`). Add one transform model, document/save revisions, and file-identity/conflict state.

### P1 — Expensive work is synchronous on the UI update path

`updateNSView` performs reload and command dispatch; decode, composite, and encode are synchronous, and composition allocates an 8-bit four-channel bitmap (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:225-258,391-470`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasViewRendering.swift:84-135`). Move decode, proxy generation, render, and encode into cancellable services, publishing state on the main actor.

### P2 — Fidelity policy and documentation are inaccurate

Composition forces 8-bit Device RGB and persistence writes one extension-selected frame with fixed lossy quality for JPEG/HEIC/HEIF/WebP; the persistence API has no source ICC, bit-depth, metadata, animation/page, or auxiliary-image input (`projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasViewRendering.swift:99-116`; `projects/crispyvibes/crispyvibes/Data/Services/RasterImagePersistenceService.swift:40-112`). The threat model credits open-time URL standardization with mitigating T05, but `standardizedFileURL` (`projects/crispyvibes/crispyvibes/Features/ContentViewer/Models/ContentViewerTab.swift:10-17`) neither resolves/revalidates symlinks nor checks device/inode identity before overwrite. It also claims progressive/bounded operations, keyboard accessibility, and logged file operations, but the reviewed implementation tracks size/date, synchronously returns one preview/fallback, handles canvas interaction through mouse events, and reports save status without a logging call (`specs/features/editor/previews/threat-model.md:56-61,73-90`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:225-258,425-490`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:200-270`). Mark those compliance statements unsupported until implemented and tested.

The reviewed SwiftUI/AppKit/coordinator types also lack explicit type-level `@MainActor`, and the 521-line representable exceeds the 400-line split-review threshold (`projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImagePreviewHost.swift:36`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/RasterImageFilePreview.swift:1-521`; `projects/crispyvibes/crispyvibes/Features/Editor/Support/EditableRasterImageCanvasView.swift:3`; `.kiro/steering/coding-guidelines.md:36-42,58-65`; `specs/technical/architecture.md:264-265`).

## Phase 0 outcome (2026-10-01)

Phase 0 fixed top-left crop pixel mapping (including the crop Y inversion), EXIF 1–8 normalization on full-resolution and proxy decode paths, orientation-1 export, pending-marquee semantics, Revert-to-loaded/saved baseline, ⌘S routing, in-flight save locking, fidelity-based overwrite blocking, and external-change conflict choices. ## Phase 1 outcome (2026-10-01)

Phase 1 replaced mutable proxy-backed editing with `RasterImageDocument`: an immutable `.file(URL)` or `.memory(CGImage)` source plus ordered `ImageEditOperation`s and a revision. File canvas units are oriented source pixels. `RasterImageEditSession` owns display replay and snapshot Undo/Redo history (maximum 200); geometric operations flatten preceding overlays before changing canvas space, and Revert is undoable. Toolbar and responder-chain Undo/Redo now support ⌘Z/⇧⌘Z with menu validation.

Display decode now runs off-main with a loading placeholder, load-generation rejection, and first-open Fit to Window. A display proxy is discardable: Save and Copy use the injected `RasterImageExportService` serial queue to re-decode file sources at full resolution, replay operations, and deliver cancellable results on the main actor. Save rejects stale revision/session output before persistence. Proxy resolution therefore no longer blocks overwrite; multi-frame, >8-bit, and HDR gain-map sources remain blocked.

Raster file identity now includes `fileResourceIdentifier` in addition to size and modification date, detecting same-size atomic replacement, and Save rechecks identity before export. This narrows but does not eliminate the final check-to-write TOCTOU window. Service contracts live in `Protocols/RasterImageEditing.swift`; production dependencies flow from `AppContainer.makeRasterImageEditorServices()` through `MarkdownViewModel`, `ImageFilePreview`, and `RasterImagePreviewHost` into `RasterImageEditorViewModel(services:)`. ## Phase 1 audit fixes and Phase 2 outcome (2026-10-01)

The post-Phase-1 audit closed the remaining crop, lifecycle, save-race, remote-staging, command-delivery, focus, and localization gaps. `RasterImageCropGeometry.coveringPixelRect` now uses independent X/Y bitmap scales, outward coverage, and a 1e-6 integer snap; both `RasterImageCanvasTransform.pixelRect` and `RasterImageRenderer` use it, preventing a rounded proxy from growing an aligned crop by a pixel. `RasterImageEditorViewModel.shutdown()` increments `operationGeneration`, cancels Save/Copy/Export, resets busy and post-save-reload flags, and unlocks the canvas; asynchronous completions compare that generation and ignore late results.

Local Save still checks file identity before rendering and now checks again immediately before writing, returning `RasterImageSaveError.fileChangedDuringSave` if the source changed during render. A successful file-source Save remains locked through `isAwaitingPostSaveReload` while the written file is decoded into a fresh session, so the visible clean baseline matches the persisted pixels that the next file export will decode. For remote images, a polling-token change calls `refreshStagedRemoteImage()` to mirror source bytes into staging; the local observer then reloads clean state or raises Reload/Keep for pending work. `saveImagePreviewData` revalidates `lastRemoteModificationToken` before upload, fails with `remoteChanged` and refreshes staging on mismatch, and records the successful write's token.

⌘S now crosses the owner/editor mount boundary as `RasterImageSaveRequest`: `MarkdownViewModel` retains pending versus handled tokens, and `RasterImagePreviewHost` acknowledges only when a renderable editor consumes the request, yielding exactly-once delivery. ## Final audit fixes and known limitations (2026-10-01)

The final audit closed the remaining lifecycle, accessibility, compositing, history, and maintainability gaps:

- `AnalysisToken` now includes editor generation, session identity, and revision. Every load/reload, including the same path, calls `cancelAnalysis()`, cancels in-flight work, and clears OCR boxes. Analyzer methods return `RasterImageWorkHandle`; cancellation calls `VNRequest.cancel()`, suppresses completion, and is also performed by shutdown.
- Background-removal Save gating now covers GIF's 1-bit transparency in addition to JPEG/JPG and BMP.
- Markup accessibility children are pressable buttons that select their item. Canvas custom actions provide selected-item Delete/Move and crop Shrink/Expand/Move/Apply/Cancel, so crop is pointer-independent.
- A live composite is used only for the matching session and revision while no item is dragged; failed rendering clears an older composite.
- History coalescing ends after one second of inactivity or a selection change. Repeated adjustment commits replace one `.adjust` through undoable `.set` history rather than growing the operation list.
- Large responsibilities moved into `RasterImageEditSession+Output`, `RasterImageFilePreviewCoordinatorLoading/Observation/Viewport`, `RasterImageRenderer+Pixels`, and `RasterImageOverlayPainter+Markup`.

Known limitations remain. A later geometric edit (crop/rotate/flip/straighten/resize/background removal) preserves earlier markup visually but flattens it; Undo restores editability. Local Save retains a final identity-check-to-atomic-write TOCTOU window. Remote SFTP has no provider-level compare-and-swap, and its size plus one-second mtime token can miss rapid same-size changes. Save/Export writes one 8-bit sRGB-or-source-RGB frame with orientation 1 and does not preserve EXIF/IPTC/GPS or ICC beyond the working color space; no PSD-style layered format is available. The synchronous `EditableRasterImageCanvasView.saveCompositedImage(to:)` remains for standalone use/tests and is not used by the app path.
