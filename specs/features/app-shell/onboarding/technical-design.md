# Onboarding — Technical Design

## Overview

Onboarding covers the first-launch disclaimer gate, the home dashboard (including the creation wizard and recent vibespaces), and the feature walkthrough overlay. The disclaimer is a hard gate that blocks all app interaction until accepted. The dashboard is the primary welcome surface. The walkthrough is a 6-step guided tour (currently disabled at code level).

## Architecture

### Disclaimer Gate

Presented when `AppStateFile.hasAcceptedDisclaimer` is `false`. Replaces the entire window — no toolbar or vibespace controls rendered.

**Layout:** Rounded card (max width 680pt) centered on canvas background.

**Card structure:**
1. Hero lockup — CrispyVibes mono mark icon (92×80pt), brand title "CRISPYVIBES", welcome headline, tagline "Just you and your vibe, uninterrupted"
2. "Before you continue" section (uppercase with letter-spacing) — 5 bullet points, each prefixed with accent-colored circle:
   - No telemetry
   - No crash reporting
   - As-is disclaimer
   - No liability
   - "It is just you and your vibe"
3. Keychain note (secondary text): CrispyVibes may ask once for Keychain access for a local signing key
4. Two buttons:
   - "Quit" (left, text style) → `NSApplication.shared.terminate`
   - "Accept and Continue" (right, primary style) → persists `hasAcceptedDisclaimer = true`

**Persistence:** `AppStateFile.hasAcceptedDisclaimer` — survives restarts, clearable via Settings reset.

### Launch Location Guard

`AppInstallationGuard` runs at the very start of `applicationDidFinishLaunching`, before service registration or other startup work. It classifies the app bundle location into four buckets:

- `/Applications` or `~/Applications` — normal launch, continue immediately
- Mounted DMG under `/Volumes` on a read-only volume — prompt to move
- `~/Downloads` — prompt to move
- `/private/tmp` or `/private/var/folders` — prompt to move
- Any other location — treated as a normal launch so developer builds and custom installs are not interrupted

When a transient location is detected, the guard presents a blocking `NSAlert` explaining that moving Crispy to Applications prevents duplicate Open With entries. If the user accepts, the app stages a copy into `/Applications/Crispy.app`, relaunches the installed copy with `/usr/bin/open -n`, and terminates the transient process. If the user declines, normal startup continues in place.

### Home Dashboard Layout

Rendered inside a `ScrollView`, max width 980pt, centered horizontally, 28pt horizontal padding, 42pt vertical padding. Min height fills viewport minus 84pt, vertically centered.

**Background:** Gradient from window background to canvas background, overlaid with two large blurred circles (accent + success colors) and a vertical gradient strip.

**Vertical stack (28pt spacing):**
1. Logo view
2. Dashboard grid (create card + recents when recents exist, or create card alone)
3. Utility dock

Decorative vertical spine (1pt gradient line) rendered behind grid when recent vibespaces exist.

### Create VibeSpace Card

Tappable button (348pt wide), rounded card (18pt radius), gradient background with accent glow top-left.

| Field | Value |
|-------|-------|
| Title | "Create New VibeSpace" (22pt semibold rounded) |
| Tagline | "Just you and your vibe, uninterrupted" (14.5pt semibold, accent) |
| Description | "Name your vibespace and bring your folders into one focused vibespace." (14pt, secondary, max 278pt) |
| Height | 176pt (with recents) / 184pt (without) |

Default name generated by `nextTemporaryVibeSpaceName()` — base "VibeSpace" with incrementing number if name exists.

### VibeSpace Creation Wizard

Modal sheet (560pt wide, min 420pt tall). Header: CrispyVibes mono mark, "Create VibeSpace", 3-step stepper (Name → Projects → CLI Agent).

**Step 1 — Name:**
- Text field pre-filled with generated default name
- Validation: non-empty after trim; error "Enter a name to continue."
- Buttons: Cancel (dismiss), Next: Add Projects

**Step 2 — Projects:**
- "Add Projects" button → `NSOpenPanel` (directory-only, multi-select, prompt "Add VibeSpace Folder(s)")
- Scrollable list (max 140pt) of added folders with icon, name, path, remove button
- Duplicates by standardized path silently ignored
- Validation: ≥1 folder; error "Add at least one folder."
- Buttons: Back, Next: CLI Agent (disabled when empty)

**Step 3 — CLI Agent:**
- Default CLI agent: 3-column grid of profile cards (Kiro CLI, Claude Code, Codex, Gemini CLI, OpenCode, Custom)
- Toggle selection (tap selected to deselect)
- Full Trust toggle for supporting profiles (Kiro CLI, Claude Code, Codex, Gemini CLI)
- Custom profile shows text field for CLI command
- Per-project overrides: dropdown per folder (VibeSpace Default or specific profile), inline trust toggle and custom command field
- Validation: custom commands must be non-empty
- Buttons: Back, Create VibeSpace

**Output:** `VibeSpaceCreationResult` (name, folder URLs, optional CLI selection, per-project CLI overrides). VibeSpace-level CLI profile persisted to UserDefaults.

### Recent VibeSpaces

348pt wide, min 242pt tall. Header "Recent VibeSpaces" with divider. Up to 5 entries from pool of 12 loaded from persistence.

Each row: folder icon (accent, 26×26pt rounded square), vibespace name, summary line (item count + first project name), right chevron. Tapping restores vibespace from persistence.

### Utility Dock

Pill-shaped (capsule) bar, max 470pt, three equally-spaced buttons with vertical dividers:

| Button | Icon | Action |
|--------|------|--------|
| Shelf | `books.vertical` | Reveals the Files sidebar Shelf section |
| Terminal Mode | `terminal` | Creates "Terminal VibeSpace" at home dir, terminal-only mode |
| Settings | `gearshape` | Opens App Settings → General |

### Back to VibeSpace

Button in top-right (24pt top, 28pt trailing) — visible only when `isShowingHome` is true AND `activeVibeSpaceID` is not nil. Calls `dismissHome()`.

## Data Flow

### Feature Walkthrough

Controlled by `FeatureWalkthroughController`. Currently disabled (`isWalkthroughEnabled = false`).

**Auto-presentation:** `evaluateAutoPresentation(hasVibeSpace:)` — requires enabled flag, vibespace exists, not completed (`featureWalkthroughCompleted` UserDefaults key), evaluates once per session.

**Navigation:** Next (advance or complete on last), Previous (no-op on step 1), Skip (immediate complete). Progress: "Step N of 6". Completion writes `true` to completion key.

**6 walkthrough steps:**

| Step | ID | Title | Hero Image | Shortcut Hint |
|------|----|-------|------------|---------------|
| 1 | welcome | Welcome to Crispy | WalkthroughWelcome | Cmd+Shift+N to create a vibespace |
| 2 | vibespace-dashboard | VibeSpace Dashboard | WalkthroughDashboard | Toolbar: VibeSpace Dashboard |
| 3 | views-and-layout | Views and Layout | WalkthroughViewsLayout | ⌘D (Detailed), ⌘T (Terminal Board) |
| 4 | project-shortcuts | Project Navigation | WalkthroughProjectNavigation | ⌘1…⌘9 to focus mapped projects |
| 5 | terminal-workflow | Terminal View Enhancements | WalkthroughTerminalWorkflow | Use New Terminal in Terminal Board view |
| 6 | complete | You Are Ready | WalkthroughReady | Toolbar: Walkthrough |

Each step has 2 annotations positioned at normalized coordinates on the hero image.

**Overlay:** Full-screen backdrop (black 45% opacity), centered card (max 980px) with progress text, skip button, title, message, hero slide, shortcut hint, back/next buttons.

**Re-access:** `presentFromToolbar()` resets to step 0 regardless of completion state. Note: `presentFromToolbar` is gated by `isWalkthroughEnabled`.

**UI test env vars:** `CRISPYVIBES_UI_TEST_FORCE_WALKTHROUGH`, `CRISPYVIBES_UI_TEST_DISABLE_AUTO_WALKTHROUGH`, `CRISPYVIBES_UI_TEST_RESET_WALKTHROUGH`, `CRISPYVIBES_UI_TEST_MODE` (isolated completion key suffix `.ui-test`).

## State Management

| State | Storage | Notes |
|-------|---------|-------|
| Disclaimer accepted | `AppStateFile.hasAcceptedDisclaimer` | Persisted to disk |
| Walkthrough completed | `featureWalkthroughCompleted` UserDefaults | Per-session eval guard |
| Recent vibespace IDs | `AppStateFile` (max 20) | Pruned on launch for missing dirs |
| Recent configs loaded | Up to 12 from persistence | Dashboard shows up to 5 |
| Install location classification | Derived from bundle URL at launch | No persisted state; evaluated each launch |

## Dependencies (frameworks, libraries)

- SwiftUI (sheet presentation, `ScrollView`, `ColorPicker`)
- AppKit (`NSOpenPanel` for folder selection, `NSApplication.terminate`)
- Foundation (`FileManager`, `Process`) for install relocation and relaunch

## Platform Considerations

- macOS only — `NSOpenPanel` for directory selection, `NSApplication.shared.terminate` for quit
- macOS only — install-location guard relies on app bundle paths, mounted volume attributes, and `/usr/bin/open`
- Disclaimer gate cannot be dismissed by Escape, clicking outside, or opening another surface

## Performance Constraints

- Recent vibespace config loading is bounded (max 12 configs)
- Walkthrough hero images are asset catalog resources (no network fetch)

## Migration / Rollout Notes

- Walkthrough is currently disabled at code level (`isWalkthroughEnabled = false`)
- Disclaimer acceptance survives app updates; clearable only via Settings reset
- `CRISPYVIBES_UI_TEST_SHOW_ONBOARDING` env var forces disclaimer display in UI test mode (prevents auto-accept of disclaimer)
